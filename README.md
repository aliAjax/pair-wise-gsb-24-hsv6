# hxwl-10 考古探方记录

遗址探方、地层关系与出土物坐标的**离线记录台**：纯前端运行，档案保存在浏览器 localStorage，无需后端。

## 技术栈

React + Vite + TypeScript + CSS

## 本地运行

```bash
npm install
npm run dev      # 开发，端口 5110
npm test         # 规则引擎单测 + jsdom 端到端测试
npm run build    # 生产构建
```

## 记录规则（新增 / 编辑 / 作废统一校验，任一冲突整体拒绝）

1. **坐标唯一**：同一探方内坐标点（忽略大小写与空格）不得重复；作废记录的坐标释放后可复用。
2. **深度不逆行地层**：第 1 层为最新地表层，层号越大越深；同探方内深度必须随地层号严格递增。
3. **出土物须挂靠有效遗迹单位**：填写出土物时必须关联单位编号；单位编号、类型、所属探方在全遗址内一致。
4. **作废守卫**：单位的开口记录（层位最浅的登记，即该单位的有效定义）在仍有同单位出土物记录依赖时不可作废。

冲突时：事务性拒绝、不写本地档案；表单保留全部未提交内容，错误内联标注到对应字段并自动聚焦；作废/撤销冲突在页面顶部列出指向字段与关联记录。撤销最近一次作废会按现行档案重新校验（作废期间坐标被占用等情况同样拒绝）。

## 持久化与恢复

- 仅校验通过的记录写入 localStorage（键 `hxwl-10.archive.v1`），读取时对损坏数据做结构校验，非法记录无法进入档案。
- 刷新后恢复：全部记录、类型筛选、探方检索词、最近一次作废（含原因与时间）。
- 最近一次作废支持一键撤销。

## 看板（随筛选实时重算）

探方数、地层数、出土物记录数、空关联数量、跨层异常清单：

- **单位跨层**：同一遗迹单位出现在多个地层；
- **深度逆行**：同探方内地层更浅的记录深度反而更大。

统计范围只包含当前筛选命中的活动（未作废）记录。
